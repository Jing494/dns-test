## 〇、新环境初始化（AI 首次接触本工具时必做）

AI 在**新环境**（新沙箱/新机器/刚 clone）使用本工具时，按此顺序走通，避免"依赖缺失/环境未验证"导致的假故障：

1. **确认依赖**：`bash install.sh`（缺失才装 dig+perl+curl，已齐全则跳过 sudo；无包管理器环境会给手动安装指引；装完可加 `--smoke` 直接跑验证）
2. **验证环境**：`bash smoke_test.sh`（23 项自动化，全绿 = 环境就绪；有失败先看失败项，多为网络项——对照第十一章环境差异判断）
3. **开始测试**：按第一章标准流程（先问 DNS → 版本 → 专项），或直接 `bash dns-test.sh` 交交互引导
4. **路径确认**：若命令报 "command not found" 或文件缺失，先 `find / -name "dns-test.sh" 2>/dev/null` 确认仓库实际位置

> AI 注意：**不要**在没有 `install.sh`/`smoke_test.sh` 验证的情况下直接跑测试——先验证环境，再下结论（环境问题 ≠ 工具问题，见第十一章）。

## 一、接到用户 DNS 测试需求时的标准流程

无论用户怎么表达（"测下 DNS"、"看看我家网络"、"帮我测测那个 DNS 干不干净"），AI 都按以下三步走：

### 第 1 步：确认测试目标 DNS
| 用户情况 | AI 行为 |
|---------|--------|
| 用户没指定 DNS | **必须先问**（不要自作主张直接测） |
| 用户说"默认/云南电信" | 用云南电信 4 个（`lib/core.sh` 的 DEFAULT_DNS_ADDR） |
| 用户说"阿里/腾讯" | 用内置预设（ALI_DNS_ADDR / TENCENT_DNS_ADDR） |
| 用户给了具体地址（v4/v6 均可） | 直接使用，无需再问 |

### 第 2 步：确认测试版本
| 用户表达 | 版本 |
|---------|------|
| "快点 / 大概看看 / 简单测" | **lite 精简版**（10 项，约 9 秒/DNS） |
| "详细 / 全面 / 完整 / 彻底" | **full 完整版**（16 项，约 10 秒/DNS） |
| 没说 | 默认 **lite**（快，够用） |

### 第 3 步：用户提出"专业/深入/专项"需求时 → 引导专项测试
| 用户意图 | 专项测试 |
|---------|---------|
| VoWiFi / ePDG / 手机 WiFi 通话 | 01 VoWiFi 域名全解析 + 02 多DNS交叉验证 |
| 路由器 / 家里网络 / 网关 | 03 路由器DNS转发测试（对比云南电信省级DNS） |
| 端口 / 防火墙 / 某个 IP 通不通 | tools/network/01_port_test.pl |
| DNS64 / IPv6 合成 | examples/03_dns64_check.pl |
| 反向解析 / PTR | examples/04_reverse_dns.pl |

## 八、日志截断与结果确认（AI 必读）

> AI 调用脚本时，输出常被工具截断（head/tail 截断、输出字符上限、max_tokens 等）。
> **输出不完整 ≠ 脚本出错**，先按本方法确认，再判断是否真异常。

### 1. 症状识别
| 现象 | 含义 |
|------|------|
| 只看到前半段（DNS列表、[1] A记录…） | 输出被截断，**脚本大概率还在正常跑** |
| 没看到"完成 ✓" / "综合评分" | 输出被截断，**不代表没跑完** |
| 看到了"综合评分"但没细节 | 已足够，关键结果到手 |
| 退出码非0 / `command not found` / `syntax error` | **真异常**，需要处理 |

### 2. 黄金法则：看结尾，不看开头
所有关键结果都在**最后**：综合评分、总耗时、完成标记。
```bash
# ❌ 错误示范（看开头，容易误判"没结果"）
bash full.sh 8.8.8.8 0 | head -20

# ✅ 正确示范（直接取关键结果）
bash full.sh 8.8.8.8 0 2>&1 | grep -E "综合评分|总耗时|完成"
bash full.sh 8.8.8.8 0 2>&1 | tail -15
```

### 3. 确认"跑完了"的三标记（缺一不可）
1. `完成 ✓`（结束横幅）
2. `总耗时: X分 Y秒`
3. `综合评分: N% (a/b 项通过)`

三者都在 → 测试完整成功，可以直接用结果。
只有 1/2 → 跑完了但该 DNS 被预检跳过（会显示"不可达，已跳过"）。
都没有 → 输出截断严重或脚本卡住，进入第 4 步补救。

### 4. 截断时的补救手段（按优先级）
| 手段 | 适用场景 | 示例 |
|------|---------|------|
| **grep 关键行** | 只想拿评分/耗时 | `bash full.sh 8.8.8.8 0 2>&1 \| grep -E "综合评分\|总耗时"` |
| **tail 尾部** | 想看结束状态 | `bash full.sh 8.8.8.8 0 2>&1 \| tail -10` |
| **重跑单 DNS** | 多 DNS 输出太长被截 | `bash full.sh 8.8.8.8 114.114.114.114 0`（只测第1个） |
| **tee 存文件分块读** | 结果要完整存档/多次查看 | `bash full.sh 8.8.8.8 0 \| tee results/x.log` 然后 `sed -n '1,50p'` / `tail -20` |
| **降级精简版** | 只要快出结论 | `bash lite.sh 8.8.8.8 0`（输出短一半以上） |
| **关进度噪音** | 只看统计 | `grep -v "✅\|⚠️\|━"` 过滤明细行 |

### 5. 真异常清单（这才需要报告/重跑/修复）
- 退出码非 0（如 124=超时被kill、127=命令不存在）
- 报错文本：`command not found`、`syntax error`、`division by zero`、`Permission denied`
- 所有 DNS 都"不可达，已跳过"（网络问题，非脚本问题）
- 输出里完全没有 `📡` 测试开始标记（脚本没正常启动）

### 6. 实战示例（本手册编写时的真实踩坑）
```bash
# 场景：多DNS完整版输出被 head 截断，只看到第1个DNS的A记录
bash full.sh A B C D 0 | head -20   # ❌ 看不到评分

# 应对：换 grep 只看关键行
bash full.sh A B C D 0 2>&1 | grep -E "综合评分|总耗时"   # ✅ 拿到全部4个DNS评分
```

### 7. 退出码约定（AI 判断成败用）

| 退出码 | 含义 |
|--------|------|
| 0 | 测试完成（至少 1 个 DNS 测过，评分多少是数据不是错误） |
| 1 | 脚本错误（参数非法、命令缺失等） |
| 2 | 所有 DNS 均不可达，测试未执行 |

```bash
bash lite.sh 8.8.8.8 0; echo $?   # 0=成功跑完
bash lite.sh 192.0.2.1 0; echo $? # 2=全部不可达（192.0.2.1为TEST-NET保留地址，必然不可达，仅用于演示退出码）
```
> 注意：评分 90% 也是退出码 0——退出码只表示"测试是否执行"，不表示"评分好坏"。

## 九、脚本排障与异常处理（AI 遇到报错时）

### 排查顺序（按此步骤走，别乱试）
1. **语法检查**（30 秒定位 80% 问题）：
   ```bash
   bash -n 脚本.sh     # bash 脚本语法
   perl -c 脚本.pl     # perl 脚本语法
   ```
2. **看退出码**：
   - `124` = 超时被 kill（多 DNS 没加索引参数？）
   - `127` = 命令不存在（dig/perl 没装？）
   - `1` = 逻辑错误（看 stderr 具体报错）
3. **看 stderr 而不是 stdout**：`2>&1` 合并后再 grep 错误关键词（`error`/`not found`/`denied`/`undefined`）
4. **最小复现**：从"多 DNS 完整版"降级为"单 DNS 精简版"（`bash lite.sh X 0`），确认是否只是规模问题
5. **查依赖**：
   - `command -v dig perl ping` 确认工具存在
   - `ls -la 脚本` 确认权限（需可读，755 为佳）
   - 检查 `lib/core.sh` 是否能被 source（`bash -c 'source lib/core.sh'`）

### 常见报错速查
| 报错 | 原因 | 处理 |
|------|------|------|
| `command not found: dig` | 缺 dnsutils | `apt install dnsutils` / `brew install bind` |
| `Bareword "IPPROTO_UDP" not allowed` | Perl 没导入常量 | 脚本头应为 `use Socket qw(:DEFAULT IPPROTO_UDP IPPROTO_TCP)` |
| `division by zero` | 稳定性轮次非法 | `STAB_ROUNDS` 需为正整数（脚本已自动校验回退 20） |
| `Use of uninitialized value in socket` | getprotobyname 在部分环境返回 undef | 已用 IPPROTO_UDP 硬编码修复，若仍出现检查是否旧版脚本 |
| `Permission denied` | 脚本不可执行 | `chmod 755` 或用 `bash 脚本` 方式运行 |
| 退出码 124 | 超时 | 加索引参数单 DNS 跑，或降级 lite |

## 十、结果报告模板（AI 向用户汇报的标准格式）

### 标准结构（按此组织，缺项补"未测"）
1. **一句话结论**：评分 + 星级 + 是否可用（如"云南电信DNS 97% 优秀，可放心使用"）
2. **关键指标**：A记录% / 稳定性% / 平均延迟 / 劫持 / IPv6（取自 `🔑 关键指标` 行）
3. **亮点与扣分**：具体到项（如"国际域名google解析波动-1"）
4. **建议**：可用/需关注/换DNS/查网络

### 示例A（优秀，直接给结论）
> 云南电信DNS（222.172.200.68）综合评分 **97%（75/77）优秀**。
> A记录100%、稳定性100%、延迟20ms、劫持检测正常。
> 扣分均为正常现象（PTR无记录、TTL波动）。**可作为家庭宽带首选DNS**。

### 示例B（中等，给关注点）
> 某DNS综合评分 85%（良好）。A记录 92%（个别国际域名失败）、稳定性 95%。
> 建议：如果主要在境内使用影响不大；国际访问建议换公共DNS对照测试。

### 示例C（不可用/异常，给行动项）
> 该DNS全部不可达（退出码2）——检查网络/地址是否正确；或换 `223.5.5.5` 对照。
> 若 IPv6 不可用，[7b] 不计分属正常（环境标注会说明）。

### 语气规范
- 结论明确（优秀/良好/一般/差），不给模糊话
- 区分"正常现象扣分"（PTR/CDN/公共DNS查不到运营商记录）与"真问题"（全不可达/稳定差）
- 涉及运营商 ePDG：注明"仅反映解析/部署，实际可用性需自测且设备支持"

## 十一、环境差异与评分波动（识别"假失败"）

### 环境差异导致的"假失败"清单
| 现象 | 真实原因（不是脚本问题） |
|------|------------------------|
| Windows 下脚本无法运行 | 需 WSL/Git Bash（脚本依赖 bash 特性与 GNU 工具，不支持原生 cmd/PowerShell）；详见 README FAQ |
| 端口测试 UDP "发送失败/无响应" | 沙箱 UDP 出站（非 53）受限 → 真机才能测端口 |
| IPv6 DNS 全部"不可达跳过" | 当前网络无 IPv6 → 预检自动跳过，正常 |
| baidu.com 预检失败但其他 DNS 正常 | 海外网络 baidu.com 解析慢 → 预检已改双域名（alidns.com 兜底） |
| [7] 连通性"Ping 不通" | 目标 IP 禁 ICMP / 无 ping 权限 → 该项显示不通但不算故障 |
| 国际域名（google/youtube）解析失败 | 网络环境无法访问 → 正常波动 |

### 评分波动处理
- **波动 2~3% 属正常**（网络抖动、CDN 负载均衡、缓存状态）——不用管
- **暴跌 10%+ 才需深挖**：
  1. 重跑同一 DNS 2 次，看是否复现
  2. 看具体掉哪项：`grep -E "❌|⚠️" 输出`（掉国际域名=网络；掉运营商=可能被限；掉稳定性=网络差）
  3. 对比历史（TEST_METHOD.md 实测表有基准值）
- **测试对比方法论**：对比两次结果必须**同 DNS、同版本（lite/full）、相近时间段**，否则无意义；记录日期和总耗时便于回溯

### 何时该报告用户 vs 自行处理
| 情况 | AI 行为 |
|------|--------|
| 评分波动 / 个别域名失败 | 自行重跑验证，向用户说明属正常 |
| DNS 全部不可达 | 报告网络问题，不修脚本 |
| 脚本语法/逻辑错误 | 自行修复（走排障流程）或报告 |
| 工具缺失（dig/perl） | 提示安装，不硬跑 |

## 十二、趋势洞察（trends.sh，历史数据聚合）

### 何时用
- 用户问"这个DNS最近稳不稳/变慢没有" → 有趋势数据就直接答
- 数据来源：compare.sh 每次运行自动存 `results/compare-<时间戳>.json`（至少 2 次才能出趋势，建议积累 7+ 天）

### 常用命令
```bash
bash trends.sh                    # 全部DNS趋势总览（文本，含均值/趋势箭头）
bash trends.sh --html --csv       # 生成 trends/report.html（SVG折线图）+ trends.csv
bash trends.sh 223.5.5.5          # 只看指定DNS
bash trends.sh --detail --limit 5 # 每个DNS列最近5条明细
bash trends.sh --since 2026-08-01 # 只看该日期后数据
bash trends.sh --cron 223.5.5.5 119.29.29.29  # 先采集(跑compare)再聚合，配crontab自动积累
```
- 环境变量：`TRENDS_DIR`（产物目录，默认 trends/）、`COMPARE_RESULTS_DIR`（数据源，默认 results/）

### 趋势箭头语义（重要，别读反）
- **评分**: `↑ 变好` / `↓ 变差` / `→ 平稳` / `↗ 微升` / `↘ 微降`
- **延迟**: 同样箭头代表"好坏方向"——`↑ 变好` = 延迟在下降（变快了），`↓ 变差` = 延迟在上升（变慢了）
- 判定方法：线性回归斜率为主（≥3 样本），首尾对比为辅（2 样本）

### 常见坑
- `trends.sh` 显示"无数据" → 先跑过 compare.sh 吗？results/ 下有 compare-*.json 吗？
- 样本含"不可达"会被跳过统计但显示"含N次不可达"——多次不可达本身就是重要信号（网络不稳）
- 数据是累加的：不要删 results/compare-*.json（除非想清空历史）
- 沙箱开加速器时单次采集评分会波动 → 趋势线出现尖刺，属正常，看长期方向即可
